# ADR-NNN: Decision title

## Status

Proposed, Accepted, Deprecated, or Superseded. Link to a replacement ADR when
applicable. Acceptance records a design decision, not implementation completion.

## Context

Describe the problem, relevant constraints, and why a decision is needed.

## Decision

State the chosen approach and its scope. Explain why it was chosen over relevant
alternatives.

## Alternatives considered

Explain relevant alternatives and why the proposed approach is preferred. Omit
this section if the comparison is already covered under Decision.

## API examples

Include concise usage examples when an API is involved. Omit this section when
it does not apply.

## Implementation notes

Record important behavioral contracts, compatibility requirements, and delivery
constraints. Omit this section when it does not apply.

## Consequences

Describe the benefits, tradeoffs, limitations, and follow-up work that result
from the decision.
